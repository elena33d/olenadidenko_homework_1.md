Примітка: дослідження виконано в Linux-середовищі GitHub Codespaces.

## Завдання 1. Аналіз відкритих портів

```bash
ss -tuln
```

Знайдені відкриті порти:

- TCP порт: 2222 → SSH (sshd), стан: LISTEN
- TCP порт: 8080 → локальний веб-сервер (python3 -m http.server), стан: LISTEN
- TCP порт: 53 → DNS-резолвер systemd-resolved (127.0.0.53), стан: LISTEN
- UDP порт: 53 → DNS-резолвер (127.0.0.53), стан: UNCONN
- UDP порт: 68 → DHCP client, стан: UNCONN

Пояснення: для TCP стан очікування з'єднань називається LISTEN. UDP не встановлює з'єднань, тому для нього показується UNCONN. Адреса 0.0.0.0 означає, що порт доступний на всіх інтерфейсах, а 127.0.0.1 — лише локально.

## Завдання 3. Перевірка TCP-з'єднання

```bash
nc -vz google.com 80
```

Результат:
```
Connection to google.com (172.217.171.110) 80 port [tcp/http] succeeded!
```

Тип з'єднання: TCP
Порт: 80 (HTTP)
Результат: з'єднання встановлено

Пояснення: `-v` дає докладний вивід, `-z` лише перевіряє, чи порт відкритий, без передачі даних. Слово succeeded означає, що завершився трикроковий handshake (SYN → SYN-ACK → ACK). Також видно, що доменне ім'я google.com було перетворено на IP-адресу 172.217.171.110 через DNS.

## Завдання 4. Порівняння TCP vs UDP

```bash
nc -vz 8.8.8.8 53
nc -u -vz 8.8.8.8 53
```

Результат:
```
Connection to 8.8.8.8 53 port [tcp/domain] succeeded!
Connection to 8.8.8.8 53 port [udp/domain] succeeded!
```


Порівняння:

| | TCP | UDP |
|---|---|---|
| Встановлення сесії | так (трикроковий handshake) | ні (connectionless) |
| Підтвердження від сервера | є (SYN-ACK) | немає |
| Достовірність результату `nc` | висока: порт точно відповів | низька: лише відсутність помилки |

Висновок: обидві команди показали succeeded, але значення різне. У TCP `nc` справді встановив з'єднання з 8.8.8.8:53, тобто сервер відповів. У UDP немає handshake, тому `nc` лише надсилає пакет і вважає перевірку успішною, якщо не отримав ICMP-помилку (port unreachable). Це не гарантує, що сервіс щось відповів. Порт 53 використовується для DNS: звичайні запити йдуть через UDP, а TCP використовується для великих відповідей.

## Завдання 5. DNS резолвінг

```bash
dig wikipedia.org
```

Результат (ключові рядки):
```
;; ANSWER SECTION:
wikipedia.org.          180     IN      A       185.15.59.224

;; Query time: 13 msec
;; SERVER: 127.0.0.53#53(127.0.0.53) (UDP)
```

Домен: wikipedia.org
IP: 185.15.59.224
DNS сервер: 127.0.0.53

Пояснення: запис типу A зв'язує доменне ім'я з IPv4-адресою. Значення 180 — це TTL (скільки секунд відповідь можна кешувати). DNS-сервер 127.0.0.53 — це локальний резолвер systemd-resolved, який приймає запит і пересилає його далі до зовнішніх DNS-серверів. Те, що він слухає порт 53 на 127.0.0.53, ми бачили в завданні 1 (TCP і UDP 53).
