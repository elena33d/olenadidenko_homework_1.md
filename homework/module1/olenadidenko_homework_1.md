Домашнє завдання №1. Основи комп’ютерних мереж

Примітка: дослідження виконано в Linux-середовищі GitHub Codespaces. Наведені IP-адреси та маршрути стосуються віртуального середовища, а не локальної мережі мого Mac.

Завдання 1. Дослідження мережі

Команда

ip a

Результат

1: lo: <LOOPBACK,UP,LOWER_UP> mtu 65536 qdisc noqueue state UNKNOWN group default qlen 1000
    link/loopback 00:00:00:00:00:00 brd 00:00:00:00:00:00
    inet 127.0.0.1/8 scope host lo
       valid_lft forever preferred_lft forever
    inet6 ::1/128 scope host
       valid_lft forever preferred_lft forever
2: eth0: <BROADCAST,MULTICAST,UP,LOWER_UP> mtu 1500 qdisc mq state UP group default qlen 1000
    link/ether 00:0d:3a:c7:d5:a0 brd ff:ff:ff:ff:ff:ff
    inet 10.0.10.201/16 metric 100 brd 10.0.255.255 scope global eth0
       valid_lft forever preferred_lft forever
    inet6 fe80::20d:3aff:fec7:d5a0/64 scope link
       valid_lft forever preferred_lft forever
3: docker0: <NO-CARRIER,BROADCAST,MULTICAST,UP> mtu 1500 qdisc noqueue state DOWN group default
    link/ether 02:42:ff:32:8d:3c brd ff:ff:ff:ff:ff:ff
    inet 172.17.0.1/16 brd 172.17.255.255 scope global docker0
       valid_lft forever preferred_lft forever

Аналіз результатів

* Інтерфейс: eth0 — основний мережевий інтерфейс віртуального середовища.
* Тип підключення: віртуальний Ethernet.
* MAC-адреса: 00:0d:3a:c7:d5:a0.
* IP-адреса: 10.0.10.201.
* Маска підмережі: /16, що відповідає 255.255.0.0.
* Gateway: 10.0.0.1.
* Broadcast: 10.0.255.255.
* Кількість можливих адрес вузлів: 65 534.

IP-адреса та маска належать до третього рівня моделі OSI — мережевого. MAC-адреса належить до другого рівня — канального.

Маска /16 означає, що перші 16 бітів адреси використовуються для визначення мережі, а решта 16 бітів — для адрес вузлів. Кількість доступних адрес вузлів у звичайній IPv4-підмережі такого розміру обчислюється за формулою 2^16 − 2 = 65 534. Віднімаються адреса мережі та широкомовна адреса.

Завдання 2. Дослідження маршрутизації

Команда

ip r

Результат

default via 10.0.0.1 dev eth0 proto dhcp src 10.0.10.201 metric 100
10.0.0.0/16 dev eth0 proto kernel scope link src 10.0.10.201 metric 100
10.0.0.1 dev eth0 proto dhcp scope link src 10.0.10.201 metric 100
168.63.129.16 via 10.0.0.1 dev eth0 proto dhcp src 10.0.10.201
169.254.169.254 via 10.0.0.1 dev eth0 proto dhcp src 10.0.10.201
172.17.0.0/16 dev docker0 proto kernel scope link src 172.17.0.1 linkdown

Аналіз результатів

Маршрут за замовчуванням має вигляд:

default via 10.0.0.1 dev eth0 proto dhcp src 10.0.10.201 metric 100

* Gateway: 10.0.0.1.
* Інтерфейс: eth0.
* Джерельна IP-адреса: 10.0.10.201.
* Протокол отримання маршруту: DHCP.

DHCP (Dynamic Host Configuration Protocol) — протокол динамічного налаштування вузлів, який дає змогу автоматично отримувати мережеві параметри, зокрема IP-адресу, маску підмережі та шлюз. У виводі ip r позначення proto dhcp вказує, що маршрут було додано через DHCP.

Завдання 3. Знаходження публічної IP-адреси

Команда

curl ifconfig.io

Результат

23.97.62.116

Порівняння та аналіз

Локальна IP-адреса віртуального середовища — 10.0.10.201, а публічна IP-адреса, яку повернув сервіс ifconfig.io, — 23.97.62.116. Ці адреси різні.

Локальна IP-адреса використовується для зв’язку всередині приватної мережі. Публічна IP-адреса використовується для доступу до зовнішніх ресурсів в інтернеті. У цьому випадку робота виконується в GitHub Codespaces, тому зовнішній трафік проходить через хмарну мережеву інфраструктуру. Публічна адреса, яку бачить зовнішній сервіс, не обов’язково є адресою самого віртуального мережевого інтерфейсу.

У домашній мережі схожий принцип реалізується за допомогою роутера та NAT (Network Address Translation). Роутер дає змогу пристроям із приватними IP-адресами обмінюватися даними з інтернетом через публічну адресу. Однак результати цього дослідження стосуються саме хмарного середовища Codespaces, а не домашнього роутера.
